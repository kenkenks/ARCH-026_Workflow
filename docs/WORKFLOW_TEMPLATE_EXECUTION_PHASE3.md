# Phase 3: チケットとひな型の接続（限定的な模擬実行）

- 保存済みひな型のID/Versionを、提出済みチケットの「実行開始」で選択する。
- ひな型を検証し、登録済み・有効なJOBカタログから表示名を解決する。
- `JOB` と `END` の直列/遷移定義を既存 `CWorkflow` / `CWorkflowMonitor` に接続する。
- チケットには実際に選択した定義ID/Versionと実行IDを記録する。
- 実行で参照した定義Versionは、サーバー稼働中に上書き・削除できない。

## 安全上の制限

**実行は模擬実行であり、JOBの業務処理は呼び出さない。** `CDummyJob` を用いて工程進行だけを検証する。`CHECK_FINAL`、`CHECK_PROVISIONAL`、`CHECK_WAIT`、イベントルートは実行不可として開始前に拒否する。判定値を捏造しない。したがって現行の審査サンプル定義はそのままでは実行できない。実行確認にはJOB→ENDの簡単なひな型を使う。

チケットと実行履歴はメモリ保持のみで、サーバー再起動で消失する。定義JSONとJOBカタログはローカルファイルに保存する。複数同時実行、公開済みVersionの不変化、業務JOB解決、判定/イベント実行、Firestore永続化は後続工程。

## 動作確認

1. JOBカタログに `demo.one` / `受付` / `CJob` を登録する。
2. ひな型 `demo` / `draft-1` に `S1 JOB demo.one → S2 END` を登録して保存する。
3. チケットを作成・提出し、「実行開始」で `demo / draft-1` を選ぶ。
4. 「1工程実行」で工程が進み、モニターに工程ID・JOB表示名と履歴が出ることを確認する。
